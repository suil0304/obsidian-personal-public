[[클래스 데코레이터#Module|@Module]]을 참고하면 좋겠구요

바로 UsersService 같은 것을 박아버리면 Mock 데이터를 넣기 힘들잖아요
또는 라이브러리에 선언된 클래스를 가져와야 한다던가

라이브러리 클래스를 가져온다는 것은 이런 거죠
[[DI를 위한 데코레이터#Inject|@Inject]]에서 가져오도록 해야 하는데 라이브러리는 당연히 @Injectable을 달아두지 않았을 테구요
그래서 등록하면서 string으로 ID를 가져오는 방식을 사용하게 할 수도 있겠죠???

```TypeScript
/**
 *
 * @publicApi
 */
export type Provider<T = any> = Type<any> | ClassProvider<T> | ValueProvider<T> | FactoryProvider<T> | ExistingProvider<T>;
```

여기에서 ValueProvider는 다음과 같습니다
```TypeScript
export interface ValueProvider<T = any> {
    /**
     * Injection token
     */
    provide: InjectionToken;

    /**
     * Instance of a provider to be injected.
     */
    useValue: T;

    /**
     * This option is only available on factory providers!
     *
     * @see [Use factory](https://docs.nestjs.com/fundamentals/custom-providers#factory-providers-usefactory)
     */
    inject?: never;
}
```

등등 여러 가지의 Provider가 존재합니다

exports에서 provide와 같은 방식으로 달아두면 내보내기가 됩니다

# ClassProvider
이 친구는 useValue 대신 useClass를 사용합니다
생성한 후 바로 DI해주구요

스코프 옵션 등을 추가적으로 설정할 수 있습니다

# ValueProvider
이미 존재하는 값을 바로 DI할 때 좋습니다

```TypeScript
import { Module } from "@nestjs/common";
import { AppService } from "./app.service.ts";

const mockAppService = { /** */ };

@Module({
	providers: [
		{
			provide: AppService,
			useValue: mockAppService
		}
	]
})
export class AppModule {}
```

AppService를 받겠다고 했을 때 실제로는 mockAppService를 DI합니다
좋잖아요

아니면 Token을 적어주는 방법도 존재하겠죠

``` TypeScript
import { Module } from "@nestjs/common";
import { AppService } from "./app.service.ts";

const mockAppService = { /** */ };

@Module({
	providers: [
		{
			provide: "AppService",
			useValue: mockAppService
		}
	]
})
export class AppModule {}
```

# FactoryProvider
```TypeScript
/**
 * Interface defining a *Factory* type provider.
 *
 * For example:
 * ```typescript
 * const connectionFactory = {
 *   provide: 'CONNECTION',
 *   useFactory: (optionsProvider: OptionsProvider) => {
 *     const options = optionsProvider.get();
 *     return new DatabaseConnection(options);
 *   },
 *   inject: [OptionsProvider],
 * };
 * ```
 *
 * @see [Factory providers](https://docs.nestjs.com/fundamentals/custom-providers#factory-providers-usefactory)
 * @see [Injection scopes](https://docs.nestjs.com/fundamentals/injection-scopes)
 *
 * @publicApi
 */
export interface FactoryProvider<T = any> {
    /**
     * Injection token
     */
    provide: InjectionToken;

    /**
     * Factory function that returns an instance of the provider to be injected.
     */
    useFactory: (...args: any[]) => T | Promise<T>;

    /**
     * Optional list of providers to be injected into the context of the Factory function.
     */
    inject?: Array<InjectionToken | OptionalFactoryDependency>;

    /**
     * Optional enum defining lifetime of the provider that is returned by the Factory function.
     */
    scope?: Scope;

    /**
     * Flags provider as durable. This flag can be used in combination with custom context id
     * factory strategy to construct lazy DI subtrees.
     *
     * This flag can be used only in conjunction with scope = Scope.REQUEST.
     */
    durable?: boolean;
}
```


useFactory로 내뱉을 것을 조립해서 하는 방식으로 가능하구요
() => {}에서 인자 부분에 들어갈 것들은 inject에서 다시 명시해줘야 하구요

# ExistingProvider
useExisting으로 별칭을 지정할 수 있습니다

이 때 provide에 들어갈 것은 다른 string 등 토큰이겠구요
useExisting에 그것을 넣으면 되겠죠
