# 응답
## HttpCode

NestJS의 기본 HTTP 상태코드가 마음에 안 든다면 사용하세요

overload도 없어요

## Header
*method*

커스텀 헤더를 추가할 수 있습니다
원래 있던 헤더 덮어쓰기도 가능하구요

시그니처는 다음과 같습니다
```TypeScript
declare const Header:(name:string, value:string | (() => string)) => MethodDecorator;
```

## Redirect
*method*

응답 후 클라이언트가 어떠한 링크로 강제 이동하도록 하고 싶다면 추천합니다
리다이렉션이잖아요?

시그니처는 다음과 같습니다
```TypeScript
declare const Redirect:(url?:string, statusCode?:number) => MethodDecorator;
```

동-적 리다이렉션을 원하신다면 body가 다음과 같으면 됩니다
```TypeScript
type RedirectBody = {
	"url":string,
	"statusCode":number
};
```

# 요청과 관련된 매개변수 데코레이터
## Param
간단합니다
경로 매개변수의 값을 가져옵니다

Param의 매개변수를 비워서 사용할 경우 수식한 매개변수는
```TypeScript
{ [key:string]:string }
```
일 확률이 높습니다

main.ts에서 ValidationPipe를 사용 설정한 후 transform을 키면 자동 변환은 해주거든요?
Param은 파이프도 받으니 검증을 하면 더 좋을 것 같네요

또는 옵션을 받을 수도 있습니다
```TypeScript
/**
 * The options that can be passed to a handler's parameter decorator, such as `@Query()`, `@Body()`, and others.
 * These options allow you to specify a schema for validation and transformation, as well as any pipes to apply to the parameter.
 */

export interface ParameterDecoratorOptions {
    /**
     * The schema to use to retrieve within the pipes,
     * to, for example, validate the parameter against the schema or to apply transformations based on the schema.
     */
    schema?: StandardSchemaV1;

    /**
     * The list of pipes to apply to the parameter.
     */
    pipes?: (Type<PipeTransform> | PipeTransform)[];
}
```

schema는 어느 검증 라이브러리에 종속되지 않도록 구성된 인터페이스입니다
스키마 검증도 가능하다는 소리임

## HostParam
*param*

[[클래스 데코레이터#Controller|Controller]]를 보면 하위 도메인 라우팅 해서 도메인을 분기해 받도록 하는 것이 있었단 말이죠?
host에 경로 매개변수 지정하듯이 지정해서 가져올 수 있습니다
좋네요

코드는 이런 느낌입니다
```TypeScript
import { Controller, Get, HostParam } from "@nestjs/common";

@Controller({ host: ":version.api.localhost" })
export class ApiController {
    @Get()
    getTest(@HostParam("version") version:string) {
        return `API Test ${version}`;
    }
}
```
