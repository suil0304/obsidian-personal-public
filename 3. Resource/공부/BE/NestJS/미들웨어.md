얘네가 Express에 기반을 둔 만큼 [[3. Resource/공부/BE/용어/미들웨어|미들웨어]]도 기본적으로는 똑같습니다

Express 공식 문서에 따르면 미들웨어는 다음과 같은 동작을 할 수 있다고 나와 있구요
- 어떤 형태의 코드라도 수행할 수 있다.
- 요청과 응답에 변형을 가할 수 있다.
- 요청/응답 주기를 끝낼 수 있다.
- 여러 개의 미들웨어를 사용한다면 `next()`로 호출 스택 상 다음 미들웨어에 제어권을 전달한다.

요청/응답 주기를 끝낼 수 있다는게 도대체 무슨 소리일까요

요청 안 넘기고 가만히 있으면 이 주기가 안 끝나잖아요
마찬가지로 예외 처리 안 해도 그렇구요

또는 현재의 미들웨어가 응답/예외 처리를 끝내지 않을 것이면서 next를 호출하지 않고 있으면 그 미들웨어에서 계속 루프를 돌 것이구요
어플리케이션이 멈추게 되겠죠

# 클래스
## 한계점
당연하겠지만 완벽한 플랫폼 독립을 지키면서 request나 response의 내부 값을 정확하게 가져올 수 없습니다

Express 타깃이면 Request,
Fastify 타깃이면 FastifyRequest
이런 방식으로 종속되게 사용할 수밖에 없다는 소리인 것입니다

아쉬운 거죠

## HttpAdapterHost
```TypeScript
import { Injectable, NestMiddleware } from "@nestjs/common";
import { HttpAdapterHost } from "@nestjs/core";

@Injectable()
class TestMiddleware implements NestMiddleware {
	constructor(
		private readonly __httpAdapterHost:HttpAdapterHost
	)
	
	use(_request:any, _response:any, next:(error?:any) => void) {}
}
```

이런 느낌으로 HttpAdapterHost로 가져와 하는 방법이 있겠는데
그럼에도 불구하고 플랫폼 독립 지키면서 가져오는 방법은 없으니 그렇게 아세요

function testMiddleware(req:any, res:any, next:(error?:any) => void) {}

이렇게 하면 됩니다

사용할 때는 이렇게 하시면 됩니다

```TypeScript
import { testMiddleware } from "./middlewares/test.middleware.ts";

async function bootstrap() {
	const app = await NestFactory.create(AppModule);
	
	app.use(testMiddleware);
	
	await app.listen(process.env["PORT"] ?? 3000);
}

void bootstrap();
```
