*Command Query Responsibility Separation*

말 그대로 명령과 질의의 책임을 분리하는 것입니다
[[CQS]]를 확장한 느낌이라 볼 수도 있을 것 같네요

Command와 Query는 모델 자체적으로도 분리될 수 있다고 믿는 아키텍처적 관점이라 설명할 수 있습니다

이미 단일 책임 원칙이 있는데 굳이 더 필요한가 싶으실 수도 있어요
서로 상호보완적으로 나아갈 수도 있는 그러한 것입니다

SRP가 서비스를 책임대로 나누고 CQRS가 그것을 Command 모델과 Query 모델로 나눠 책임을 다시 한 번 나눌 수 있게 만든다는 거죠

그러면 굳이 정규화해둔 RDB를 다시 조회 속도를 위해 반정규화해야 하나 고민할 필요도 없이 Redis 등에 캐시된 데이터로 보내기만 하면 되고
그래서 Query와 Command 간의 독립성을 눈여겨볼 수 있다

어떻게 보면 AOP를 더 잘 지키면서 코딩하고 싶은 사람들의 이야기처럼 들리기도 하는데
아쉬운 거죠
아아 관점지향이여
