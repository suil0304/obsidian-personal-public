*JSON Web Token*

어디서 많이 들어본 이름이잖아요

대충 JSON 안에 인식 정보 등을 담아두고 그것을 서명해서 암호화한 다음 사용자가 저장하게끔 하는 방식입니다

# 표준 등록 헤더
- typ(type, 유형)
	표준 JWT에서는 "JWT"으로 두시면 됩니다
- alg(algorithm, 서명 알고리즘)
	알만 하잖아요
	이에 대해서 자주 쓰이는 알고리즘은 다음과 같다고 하구요
	- HS256(HMAC SHA-256)
		대칭키 방식입니다
		비밀키 하나로 검증과 발급 둘 다 하는 것이구요
	- RS256(RSA SHA-256)
		비대칭키 방식입니다
		개인키로 토큰을 발행하고 공개키로 검증하는 것이구요

# 표준 등록 클레임
페이로드에 들어가는 것들을 클레임이라 부르구요

- sub(subject, 주제)
	이 JWT의 주인이 누구인지를 담습니다
- iss(issuer, 발행자)
	발급한 주체가 누구인지를 담습니다
	회사의 도메인이나 인증 서버의 이름을 넣는다고 하네요
- aud(audience, 대상자)
	이 토큰을 받아 처리할 대상입니다
- exp(expiration time, 만료 시간)
	만료되는 시각이구요
- nbf(not before, 활성 시각)
	토큰이 활성화되는 시각이구요
	이 시기 전에 왔다면 거절하면 되겠네요
- iat(issued at, 발급 시간)
	토큰이 발급된 시간입니다
- jti(jwt id, 요청 고유 식별자)
	JWT 자체의 식별자입니다

# 공개 클레임
표준에 덧붙여서 공개되어도 무방한 것들을 공개 클레임으로 하자고 하는 것인데
이름 충돌이 당연히 날 수도 있으니 도메인 + 클레임으로 하기도 합니다

```JSON
{
	"http://example.com/is_root": true
}
```

# 구조
궁금해서 알아보았습니다

.을 기준으로 3개로 나뉜다고 하네요
헤더 -> 페이로드 -> 서명
여기에서 서명은 헤더와 페이로드를 Secret Key 등으로 암호화한 값이라 하구요
