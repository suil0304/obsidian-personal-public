그렇다면 V-Slice는 네트워킹을 허용하는가?

우리들의 믿지는 못 하겠고,
반 정도 믿을 만한 친구인 ChatGPT를 통해 간접적으로 조사해보자.

그 때 밖에 나가 있어 GitHub 접속하기 귀찮은 환경이었다는 것은 아쉬운 것일 뿐이고,
어쨌거나 좋지 아니한가?

> [!note]+ 프롬프트: 진짜 바닐라 FNF V-Slice 네트워크 관련 샌드박싱 우회 못 하나
> 아마 네가 말하는 게 **V-Slice의 HScript/Polymod 샌드박스에서 네트워크 접근이 막혀 있는 부분**이라면, 결론부터 말하면 **“모드 코드만으로 샌드박싱을 우회해서 임의의 네트워크 요청을 보내는 것”은 사실상 기대하면 안 돼.**
> 
> V-Slice의 공식 모딩 시스템은 HScript 기반이고, 공식 문서도 스크립트를 모드 콘텐츠로 로드하는 구조를 전제로 하고 있어.
> 
> 특히 중요한 건 이게 단순히
> 
> > `Http` 같은 API를 못 쓰게 막아놨다
> 
> 수준이라면 다른 접근법을 찾을 여지가 있지만, **스크립트 실행 환경 자체에서 허용된 API만 노출하는 형태의 샌드박싱**이라면 HScript 코드에서 다른 Haxe/OpenFL/Lime API를 찔러보는 방식으로 해결되는 문제가 아니야.
> 
> 그래서 네가 생각하는 목적이 **“V-Slice 모드에서 서버와 통신하고 싶다”**라면 방향은 보통 두 가지야.
> - **바닐라 V-Slice가 공식적으로 제공하는 네트워크 관련 API가 있는지 확인**
> - 없다면 **엔진 자체를 수정해서 신뢰된 네이티브 코드가 네트워크 기능을 제공하고, HScript에는 제한된 인터페이스만 노출**
> 
> 두 번째 방식이면 예를 들어 모드 스크립트가 직접 소켓을 여는 게 아니라,
> 
> `HScript → 게임이 제공하는 제한된 API → 네이티브 네트워크 코드`
> 
> 처럼 경계를 두는 거지.
> 
> 반대로 **샌드박스 자체의 제한을 뚫어서 네트워크 권한을 얻는 방법**을 찾는 거라면 그건 보안 경계를 우회하는 문제라 구체적인 우회법을 제공하긴 어려워.
> 
> 그리고 지금 공개된 V-Slice 소스에서도 Haxe/HScript 쪽에 상당히 많은 클래스가 컴파일에 포함되도록 구성되어 있는 건 확인되지만, 이것만으로 “모드가 임의 네트워크에 접근할 수 있다”는 뜻은 아니야.
> 
> **네가 말하는 게 정확히 `Http`/`sys`/`openfl.net` 같은 특정 API가 막힌 상황이라면, 그 API 이름을 알려주면 “왜 막히는지 + 바닐라에서 합법적으로 접근 가능한 경로가 있는지”까지 소스 기준으로 같이 파볼 수 있어.**

뭐, 어찌 저찌하여 sys로 가는 모든 클래스는 막혔지만,
openfl.net.Socket과 openfl.net.DatagramSocket에는 readObject 메서드 제외 접근 가능하다는 것이 어디인가.
이것은 trace로 직접 다시 확인한 내용이니 그렇게 이해하면 될 것 같고,
readObject 메서드는 왜 막아 두었는가에 대하여 적기 귀찮으니 넘기다
