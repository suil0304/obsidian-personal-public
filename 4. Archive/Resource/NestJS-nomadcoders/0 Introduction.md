> [!note]+ # #0.1 Welcome
> 기본적으로 Node.js 위에 돌아가는 프레임워크
> 특히 Express 위에서 돌아감
> *(Express는 모든 Node.js 어플리케이션의 초석과 같은 존재라고 함)*
> 
> NestJS가 멋진 이유 중 하나:
> 다른 Node.js 프레임워크에는 없는 구조를 가지고 있다고 함
> 근데 그러면 그냥 특이해서 멋져 보인다이지 않을까 싶구요
> 이러언
> 
> 이것(구조)은 또한 Node.js에도 없다고 하네요
> 
> > [!note]+ 예를 들어보다:
> > Ruby에는 Ruby on Rails라는 프레임워크가 존재함
> > 순서와 구조를 지니고 있어 제대로 따르기만 한다면 아주 맛난 Ruby 버킷을 만들 수 있다고 하네용
> > 
> > Python의 Django 또한 순서와 구조를 지니고 있는 프레임워크
> > Python으로 백엔드 구성하는 일을 아주 빠르게 해주다
> > 
> > ![[나에겐_NestJS가_있어.png]]
> > 
> > 우리에겐 Java가 있어
> > Spring이라는 프레임워크를 지니고 있음
> > 
> 
> 또한 사람들은 Spring을 선호하다
> 아주 훌륭한 안정적인 서비스를 만들기 위한 직관적인 방법이기에
> 또한 구조상 실수하기도 어렵기에
> 
> 그리고 NestJS는 위의 Spring과 같은 프레임워크의 특징을 그대로 Node.js에 import하다
> 
> 또한 Node.js의 단점(장점이나 팀 프로젝트 등에서는 그러하다)은 매우 자유롭다는 것인데
> Express로 API를 만들 때 URL을 어디에 둘지 등도 마음대로 정할 수 있다는 소리임
> 
> 그것을 TS마냥 통제하여 큰 단위의 백엔드 프로젝트도 쉽게 개발할 수 있다고 함
> ㅇㅇ
> 크하하
> 
> 이것은 객체지향, 함수형, 심지어 함수형 반응형 프로그래밍도 사용함
> 
> 매우 개-쩌는 프레임워크인!

> [!note]+ # #0.3 Project Setup
> npm으로 설치하는 것을 강력히 추천하다
> yarn으로 설치하면 문제가 생기는 듯한
> 
> ```bash
> npm i -g @nestjs/cli
> nest new project-name
> ```
> 
> 다음으로 치다
> 
> ```bash
> nest
> ```
> 
> 수일의 경우 Desktop에 새로운 프로젝트를 설치하는
> 
> ```bash
> nest new
> ```
> 
> 이것으로 새로운 프로젝트를 생성하다
> 
> 그리고 GitHub에 연결하다
